# IPasswrd для Android — как собрать и что уже умеет

Приложение то же самое, что на iPhone: `mobile/IPasswrd.Mobile` (.NET MAUI 9), общее ядро
`IPasswrd.Core` и общий файл сейфа `vault.ipvault`. Android добавлен вторым таргетом —
`net9.0-ios;net9.0-android`, весь XAML и вся логика экранов общие, различаются только
пять платформенных сервисов.

## Что перенесено

| Возможность | iOS | Android |
|---|---|---|
| Сейф, мастер-пароль, локаут 4→5м…30д | ✅ | ✅ (то же ядро, бит-в-бит тот же файл) |
| Быстрая разблокировка | Face ID / Touch ID + Keychain | Отпечаток / лицо (BiometricPrompt) + Android Keystore |
| Аккаунты, карты, документы, заметки, ключи доступа, избранное, поиск | ✅ | ✅ |
| Аутентификатор: QR-скан, ручной ввод, живые коды | AVFoundation | CameraX + ZXing |
| Генератор паролей, «Защита», настройки | ✅ | ✅ |
| Вложения (сканы) с ужатием 1600px/q80 | UIKit | BitmapFactory |
| Синхронизация: файл сейфа в облаке | iCloud Drive (security-scoped bookmark) | SAF (постоянное право на URI): Google Drive, Dropbox, локальная папка |
| Синхронизация: Google Drive напрямую | ✅ | ✅ (тот же OAuth-клиент и redirect) |
| Автоблокировка, смена мастер-пароля, экспорт копии | ✅ | ✅ |
| **Системное автозаполнение** | ждёт Apple Developer $99 | **✅ работает, ничего платить не нужно** |
| Защита от скриншотов | система сама размывает снимок | FLAG_SECURE |
| Участие в облачном бэкапе | нет | нет (`allowBackup=false` + data-extraction-rules) |

## Сборка: GitHub Actions

Workflow `.github/workflows/android-build.yml` (ubuntu-раннер, Android SDK там уже есть)
собирает APK и подписывает его постоянным ключом. В отличие от iOS, ничего не протухает
через 7 дней — поставил и забыл.

```
gh workflow run android-build
gh run watch
gh run download --name IPasswrd-android-apk
```

Готовый `IPasswrd.apk` кинуть на телефон (Google Drive, кабель, что угодно) и открыть —
Android спросит разрешение «Установка из этого источника».

## ⚠⚠ Ключ подписи — не потерять

Файл: `_signing\ipasswrd-release.keystore`, пароль рядом в `_signing\password.txt`.
Папка в `.gitignore`, в репозиторий не попадает. Копия ключа лежит в секретах GitHub
(`ANDROID_KEYSTORE_B64`, `ANDROID_KEYSTORE_PASS`, `ANDROID_KEY_ALIAS`) — оттуда его берёт
сборка. **Сделать резервную копию папки `_signing` в надёжном месте.**

Почему это важно: Android разрешает обновление только если новый APK подписан ТЕМ ЖЕ
ключом. Потеряли ключ — обновление можно поставить только удалив приложение. Отладочный
ключ .NET Android для этого не годится: он генерируется заново на каждой чистой машине,
а раннер GitHub всегда чистый, то есть у каждой сборки была бы своя подпись.

Сборка печатает SHA-1 подписи готового APK — если он вдруг изменится, это видно сразу.
Текущий: `9E:F6:72:79:D0:DA:BF:9F:09:E7:3B:67:B3:45:9E:B3:34:95:A7:94`.

## Сборка локально (если поставим Android SDK)

```cmd
dotnet build mobile\IPasswrd.Mobile\IPasswrd.Mobile.csproj -f net9.0-android -t:InstallAndroidDependencies -p:AcceptAndroidSDKLicenses=True
dotnet build mobile\IPasswrd.Mobile\IPasswrd.Mobile.csproj -f net9.0-android -p:IpwAndroidOnly=true
```

## ⚠ Два TFM и флаги сборки

У проекта теперь два таргета. Восстанавливать оба сразу можно только там, где стоят
**обе** нагрузки MAUI, поэтому:

* iOS-сборка (macOS-раннер, только `maui-ios`) → `-p:IpwIosOnly=true`
* Android-сборка (ubuntu-раннер, только `maui-android`) → `-p:IpwAndroidOnly=true`
* `-p:IpwNet9Only=true` по-прежнему нужен обоим: SDK 9 не умеет `net10`, на который
  мультитаргетится `IPasswrd.Core`.

Проверка компиляции iOS на этом ПК теперь тоже с флагом:

```cmd
dotnet build mobile\IPasswrd.Mobile\IPasswrd.Mobile.csproj -f net9.0-ios -p:IpwIosOnly=true
```

## Автозаполнение: как включить на телефоне

Настройки Android → «Пароли и автозаполнение» (или «Система → Языки и ввод → Служба
автозаполнения») → выбрать **IPasswrd**.

Дальше в любом приложении и в Chrome над клавиатурой появляется строка IPasswrd:

* сейф открыт → сразу видно подходящие записи (домен для браузера, имя пакета для приложений),
  логин и пароль подставляются одним касанием; если у записи есть код проверки и на экране
  есть поле кода — подставится и он;
* сейф закрыт → одна строка «IPasswrd — разблокировать»: открывается свой экран, там
  мастер-пароль или отпечаток, потом список записей;
* новый пароль, введённый вручную, Android предложит сохранить — запись уедет в сейф
  (если такой аккаунт уже есть, обновится пароль, старый останется в истории).

## Вход в Google на телефоне

Тот же OAuth-клиент, что на iPhone: redirect_uri — «перевёрнутый» client id, его ловит
`Platforms/Android/WebAuthCallbackActivity`. Правок в Google Cloud не потребовалось.
Если когда-нибудь понадобится отдельный Android-клиент, к нему нужен SHA-1 подписи APK —
у отладочной подписи он свой, и после смены ключа клиента придётся заводить заново.

## Файл сейфа

Локальная копия — во внутренней памяти приложения (её не видно другим приложениям и она
не попадает в бэкап). Внешний файл подключается через «Настройки → Синхронизация»:
системный выбор файла, дальше приложение держит постоянное право на чтение и запись
именно этого файла — переживает перезагрузку.

## Мелочи, которых нет на iOS (и почему)

* `FLAG_SECURE` — запрет скриншотов и превью в списке задач. На iOS система размывает
  снимок сама, на Android — нет, поэтому флаг выставлен явно.
* `allowBackup=false` + `data-extraction-rules` — сейф и ключ Keystore не уезжают в
  Google One и не переносятся на новый телефон «автоматом». Перенос — синхронизацией.
* Минимальная версия — Android 8.0 (API 26): ниже нет службы автозаполнения.
